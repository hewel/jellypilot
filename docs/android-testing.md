# Android verification and device acceptance

The Android client uses the shared Rust SDK, Compose, and the libmpv JNI host. Verification is
split at those boundaries so a passing UI test is not mistaken for decoder, device, or server
acceptance. Visual and audio/output acceptance is performed by a human.

## Automated checks

```bash
bun run task android doctor
bun run task android check
bun run task android build
```

`android check` regenerates UniFFI bindings and runs Android lint and host tests. Compose behavior
tests use Robolectric with an ordinary Android Application: they exercise selection, failure,
undo and track controls without loading the ARM64 player or taking screenshots. They do not
verify visual fidelity, native rendering, accessibility-service output, or real device timing.

The shared SDK's HTTP/storage fixtures exercise real request serialization and asynchronous
boundaries: original/direct playback, start/progress/stop reports, retryable reporting failure,
profile admission, cancelled native waiters, interruption recovery, hidden history pagination,
and collection undo. History hiding must never write Played or server resume state.

Changes to shared contracts also require the repository-wide checks in
[the validation policy](agents/validation.md). The desktop smoke gate verifies startup only.

For a connected ARM64-capable device or an emulator with working ARM64 translation:

```bash
ANDROID_SERIAL=<device> android/gradlew -p android :app:connectedDebugAndroidTest --no-daemon
```

The instrumentation suite exercises actual JNI, descriptor and Surface lifetimes, admission,
foreground/background behavior, and Keystore storage. Synthetic media is generated by the build
using host FFmpeg. A translated emulator pass is useful lifecycle evidence, but is not hardware
decoding, physical audio, HDR, or 16 KB-page runtime evidence.

The development APK is `android/app/build/outputs/apk/debug/app-debug.apk`. It includes native
symbols and is larger than a distribution build. A controlled release additionally requires its
own signing identity, install/upgrade validation, and the delivery evidence in the
[Android design specification](android-client-design-spec.md).

## Human acceptance after implementation

Record the APK hash, device/OS, server type/version and media metadata with the result. Use a
test account whose Favorites and Played flags can be changed deliberately.

1. Connect to Jellyfin and Emby using their supported login methods. Verify remembered accounts,
   temporary login, reconnect, account switch, disconnect, sign-out, and optional local Watchlist
   deletion. Failed authentication must leave existing playback intact.
2. Check Home, both personal lists, Library and Search in light/dark/system themes and English/
   Simplified Chinese. Inspect narrow and tablet windows, large text, touch targets, keyboard
   focus and TalkBack. Search/back and detail/back must retain the source filter and position.
3. Remove one and several Watchlist/Favorites entries, undo within the feedback period, and
   simulate a failed server write. Hide a History record and undo it; server progress and Played
   must remain unchanged. Unavailable saved media must remain removable.
4. Play a movie and episode from their real detail pages. Check server resume, play from the
   beginning, preplay and in-player audio/subtitle selection, external subtitles, seeking,
   episode selection, previous/next, and natural-end advance. Confirm progress on the server.
5. Exercise Intro Skipper Automatic, Manual and Off with a supported server. Automatic-skip Undo
   returns to the previous position and makes this session Manual. Focus/TalkBack must not make
   a transient action disappear while it is being used.
6. Background and return, lock/unlock, rotate, resize/split-screen, interrupt audio focus and
   unplug a headset. Returning to eligibility must stay paused. Explicit player exit ends the
   session; a playback interruption preserves its local recovery point.
7. Reclaim the process during playback, reopen, and explicitly restore the local position as a
   new session. Check this separately from server Continue Watching. Send remote start/control
   commands while visible, backgrounded, locked and switching accounts; stale commands must not
   start later.
8. Check representative SDR, HDR10 and metadata-confirmed Dolby Vision Profile 5 media, real
   audio output and styled subtitles. Record correct HDR output or SDR mapping on each supported
   device rather than inferring it from a decoder name. Test diagnostics export and cache clear.

Keep pass/fail/unavailable explicit. Activity recreation does not prove process-loss recovery;
successful decoding does not prove correct color; a debug APK does not prove signed upgrades.
